# HiPExo Ubuntu 同步采集优化版 — 2026-10-10

## 这版做了什么

每次 Record 创建独立记录目录，保留时间、受试者、地点、实际传感器命名。优先原生采集 1000 Hz；低于该频率或有读取抖动时才根据真实时间戳重采样。数值数据输出到统一的 **1000 Hz 时间轴**：每片段 **60 ms / 60 点**，每周期 **5 片段 / 300 ms / 300 点**。每周期写入本机，并通过 `DataManager.sig_cycle_ready` 提供完整数据包的本机订阅接口。本版不向 Windows 或机器人控制器发送这些周期包。

**1000 Hz 是处理输出网格，不是所有传感器的硬件采样率，也不是 1 ms 同步精度承诺。** 时间戳、有效性、插值和缺失情况都保留。相机图片不插值为 1000 fps。

## 启动和操作

已部署工作站仍使用原命令：

```bash
cd "/home/gong/Desktop/exo-control (copy)/python"
python3 hipexo_monitor19.py
```

停止旧采集、关闭旧界面后重启。先设置人员和地点，启动要采集的传感器，IMU 参考姿态按此前方式设置；按 Record 开始记录。Windows EMG 仍须桥接 ARMED，再在 EMG 页同步并开始。

默认仅保存相机深度图和时间戳，不运行地形 CNN，不启用自动地形控制。相机当前使用深度流，不是 RGB 连续录像。图片是 16 位深度 PNG，像素值乘 `depth_scale_m` 得到米；普通图片查看器可能显示较暗。

## 同步与重采样规则

- 所有网格均以本次 Record 的 Linux 单调时钟为起点；UTC 纳秒由起点映射。CSV 的 `mapped_utc_ns` 请按整数读，Excel 的有效位数不足以精确保留纳秒。
- EMG 使用现有 Windows 时钟探测和设备锚点映射；网络接收独立线程，采样时间不改成到包时间。设备内部延迟未知时仍是未知，不假设为零。
- 本地 IMU/力/电机使用各次读取后的主机时刻。IMU 同时保留一次读操作耗时；这是软件对齐，不能替代硬件触发。IMU 加速度/角速度与欧拉角由两次总线事务获取，不保证来自同一个设备内部更新周期。
- 连续量做有间隔上限的线性插值；角度沿最短圆弧插值。参考姿态编号变化时不跨界插值。不向断线区间外推。
- `quality=0` 缺失，`1` 时间戳恰好匹配，`2` 插值，`3` 保持最近 LiDAR 扫描摘要。`quality=1` 对 EMG 仍可能是上游处理网格，不代表原生 1000 Hz。
- 当前允许的相邻源样本最大间隔：IMU/力/电机 40 ms，EMG 4 ms，LiDAR 250 ms。空值代表未知；不是测量值零。每列可能另有无效值，例如尚未标定的 MVC 比例、尚未调零的相对角度。
- 默认等候 **3 秒** 收集网络和处理延迟，再按 300 ms 周期输出。可通过 `HIPEXO_SYNC_WAIT_MS` 设置 0–10000 ms。这个等候时间只增加输出延迟，不平移源时间戳。
- 已经输出后才到达的数据保留在源采样文件，计入 `late_frames`，不悄悄改写已发送周期。因此检查完整性必须看质量报告，不能只看“写盘完成”。
- 停止后末周期补齐至 300 行，尾部标记 `within_recording=0`。这些行没有有效传感器值。网格浮点数保留小数点后 9 位；源采样文件保留原精度。

## 预处理和减少冗余

- EMG 原始采样率高于 1000 Hz 时，在降采样前使用六阶 Butterworth 400 Hz 抗混叠低通；原始信号和整流后的信号分别处理，再使用现有二阶 Bessel 5 Hz 包络、baseline 和 MVC。滤波状态跨包连续，断档重置。因果滤波的相位延迟未自动扣除，滤波版本进入标定身份；旧标定不能直接复用。
- 厂商 RMS 模式保持 RMS 身份，不伪装成原始高频肌电；单位和倍率随配置保存。
- IMU 保留六轴、原始姿态、相对姿态、参考编号与读取诊断；温度降为每秒读取，磁场寄存器不再白读。
- 电机网格保留转子角度、转子角速度、温度和错误码。输出轴角度/度数可以由减速比推导，不重复写多份。未修改电机控制命令和控制参数。
- 力传感器保留 ADC 原始码、电压和标定载荷。ADS8688 按数据手册修正量程寄存器低四位编码并验证回读，以内部参考电压标称 4.096 V 换算（对应 ±10.24 V 等实际 ADC 满量程）。旧驱动的高四位写法和量程编码不正确；此前实验的换算值需复核。新版本先用已知电压/重量核验，不自动改写旧数据。`kg` 为原有标定定义的等效载荷，换算为牛顿乘 9.80665；没有把显示 Tare 自动当成硬件标定。
- 相机默认只采图，无 CNN、类别概率和重复识别字段。显示刷新与采集/保存分离。

## 性能和防冲突

力传感器采用独立采集进程，SPI 从 1 MHz 调到回读通过的 4 MHz；每个转换帧同时发送下一通道选择指令，避免重复选通事务，按 20 ms 有界批次传入界面。仍以真实读取时间记录，不把目标频率当实测频率。

相机采集、周期编码与写盘分别在独立进程，避免 RealSense 的阻塞调用和 CSV 编码占住其他采集线程。EMG socket 接收为独立线程。IMU 每条 I²C 各有一个线程，总线内部串行读取两只；同一程序/维护工具使用排他锁，避免重复打开同一总线。图表按较低频率刷新。

300 ms 周期是内存控制设计的一部分：周期落盘后释放过期样本，只保留插值所需的前一邻点及固定延迟窗口，不累积整场实验。默认 3 秒等待窗口是为跨电脑到包延迟预留的有界缓存；无法用 300 ms 分包本身保证写盘速度或同步精度。

图像编码使用独立线程，最多排队 64 帧（640×480 深度图约 37.5 MiB）；Stop 会等待已接收图像写完。周期里的图像路径可能先于图片写完出现，完整性以停止后的质量报告为准。父进程/写盘进程队列各有 64 MiB 预算与条目上限；EMG 接收队列上限 32 MiB / 512 包。超限、写盘错误、子进程退出都会报告错误并停止接受新记录、排空已接受队列，不把它们当成功；不再继续写无限空周期。不能保证任意负载都不丢数据，必须根据质量报告和压力测试验收。

## IMU 200 Hz 和实际硬件限制

四只 `(7,0x50)`、`(7,0x51)`、`(1,0x52)`、`(1,0x53)` 的 RRATE 已设为 200 Hz，并回读确认；用户确认本次按 200 Hz 使用。上电带宽寄存器保持原值 4（通用协议对应 20 Hz），未把采样率和滤波带宽混为一谈。

两条总线当前分别是 400 kHz 和 100 kHz。软件目标均为每只 200 Hz，但目前真实联采尚未读满：最新验证见 `docs/VALIDATION.md`。IMU 页面显示实读频率，原始数据也提供时间间隔。I²C-1 若要稳定接近 200 Hz，后续需核对接线/上拉并将控制器总线提高到合适速度，可能需要设备树修改和重启；本版没有擅自改内核、设备树或重启电脑。

明确维护命令（先关闭界面）：

```bash
python3 configure_imu_rate.py --hz 200 --save --output imu_rate_receipt.json
```

仅支持已核对的 10/50/100/200 Hz 通用寄存器码，不猜测 1000/2000 Hz 指令。原设置为码 6（10 Hz），如需回退可使用 `--hz 10 --save`。程序常规启动不会反复写 IMU Flash。

官方依据：[WIT 通用寄存器协议](https://wit-motion.gitbook.io/witmotion-sdk/wit-standard-protocol/wit-standard-communication-protocol)、[WT9011G4K 产品资料](https://wit-motion.yuque.com/wumwnr/docs/cokn95)。

## 安装、回退与开发

`python/` 是 Ubuntu 界面的代码快照。现有设备应先备份，再复制代码；保留本地 `emg_config.json`、`emg_license.local.json`、LiDAR 串口配置和厂商 SDK。电机可用 `python3 build_motor_io.py --sdk-root "/home/gong/Desktop/exo-control (copy)"` 从本机已有 SDK 编译释放 Python GIL 的包装模块；本次工作站已构建。串口等待期间允许其他采集线程运行，读写命令由锁保护，SDK 返回失败不会记录旧值为新样本。该修改不缩短 USB 应答的物理时间，不修改控制参数。GitHub 不分发厂商库和本机编译二进制。

安装额外性能依赖：`python3 -m pip install --user -r requirements-sync.txt`。RealSense、Qt、NumPy、SciPy、OpenCV 和原有 SDK 仍由现有环境提供。

`HIPEXO_RECORDING_MODE=legacy` 可临时恢复原长表 Record；显式指定 CSV 路径的旧 API 也保持兼容。`HIPEXO_VISION_MODE=inference` 可恢复旧地形识别流程，性能隔离保证仅覆盖新的 images 模式。完全回退使用本地备份目录，详见工作站部署记录。

本机周期订阅示例：

```python
# 在按 Record 之前连接订阅者。无订阅时不会把完整周期包传回 GUI 进程。
# 处理函数应尽快把包放入有界工作队列，不在 GUI 回调里执行耗时运算。
window._dm.sig_cycle_ready.connect(consume_cycle)
# packet['rows'][0:60] 是片段0，依次到 [240:300] 为片段4。
# 列定义从 pipeline_schema.json 的 columns 获取。
```

本接口只有数据，不发送电机控制命令。网络协议、接收端确认和重传属于后续接入工作。
