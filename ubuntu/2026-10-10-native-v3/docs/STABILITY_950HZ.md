# V3.2：950 Hz电机与IMU交接稳定性

## 为什么之前会低于980 Hz

前一轮20分钟试验的995 Hz请求，两路原生反馈每秒计数最小978/982，平均991.720/992.924 Hz。全程发送数、有效反馈数和原生CSV条数一致，CRC坏字节与发送错误均0。证据指向请求调度/交付抖动，而不是已观察到的反馈帧丢失；没有设备序号，不能据此证明硬件内部完全无丢样。

代码中，唤醒迟到后若触发750 μs最小间隔，旧逻辑会重设下一次截止时间；超过一个周期时也直接以当前时刻重新起算。短延迟于是会使后续发送时间表不断后移。仅把目标改成950 Hz并不能修复这种累积偏移。

新版保留原始频率时间表，下一次可发送时间取“原截止时间”和“上次发送完成+750 μs”的较晚者；迟到超过整周期时明确计数并跳过，继续对齐原时间表。保持半双工最小发送间隔，没有连续突发追赶。实际发送仍受Linux调度与USB影响，不能承诺严格等间隔的硬实时反馈。

默认请求改为950 Hz，原生CSV保留全部实际反馈；统一处理网格仍为1000 Hz，按真实时间戳插值。质量标记和长空档不插值规则不变。主动电机控制仍使用SDK原路径。

## IMU空档调查

20分钟记录中，每只IMU都只有一次大于10 ms的间隔，集中在第412.47秒附近：I²C-7为189.7 ms，I²C-1为226.3 ms。恢复时单次寄存器读取耗时仍约1–2 ms；力、电机没有同步发生这种长空档。两条总线共同停顿，不像某一只IMU接触不良的独立错误。

旧IMU子进程调用阻塞式socket.sendall。用模拟I²C和缩小的真实socket缓冲重现界面停止接收后，随后150 ms内原生读取次数为0。新版复用ADS8688已有的PacketSender，非阻塞泵送并限制待发数据为256 KiB，停止时有界排空；过载明确失败，不无限占用内存。同一测试现在持续读取，回归通过。

这证实了一条能造成采样暂停的代码路径，但原20分钟记录没有记录sendall阻塞耗时，不能把它写成已经百分之百定位的历史根因。

用户确认外骨骼悬挂静止，缺少明显波峰波谷是预期现象。原记录中的孤立角速度尖峰和Yaw变化仍作为待核实的测量异常保留；本版没有用滤波删除异常，也没有重新标定IMU。

## 测试

- 17项Python回归通过：零输出协议/CRC、频率参数、监测切换、IMU慢接收端、IPC、重采样。
- C++调度测试使用生产头文件，验证反复短延迟后回到原时间表、750 μs最小间隔、整周期跳过计数，以及950/995/1000 Hz一秒窗口计数。
- 两次180秒完整Qt离屏界面对照：第一次只把旧调度目标设为950 Hz；第二次启用新版电机调度和IMU非阻塞交接，目标同为950 Hz。八路采集，零输出电机指令，每30秒切换页面。
- 相机、EMG、LiDAR未参加。短时对照没有代替新的20分钟长测。实验期间常规工作站负载未做严格控制，对比不是硬件恒定负载基准。

## 180秒对照结果

|配置|Motor 0 平均Hz / 每秒范围|Motor 1 平均Hz / 每秒范围|
|---|---|---|
|旧调度，目标950|947.798 / 939–951|948.131 / 939–951|
|新调度，目标950|949.203 / 943–951|949.214 / 943–951|

每秒计数标准差从2.042/2.031降到1.228/1.296。修复后电机最大主机间隔为6.626/7.595 ms；第二路最大间隔并未改善，仍存在系统/USB交付抖动。两次试验最终发送数与有效反馈数分别一致，坏字节与发送错误均0。

新调度整周期错过数为145/142（包含启动和收尾），仍会少发请求；它解释了剩余的目标与平均速率差异。**默认950 Hz代表请求目标，不是每秒至少950个反馈或硬件严格等间隔的保证。**

修复后四路IMU均约200 Hz，最大间隔6.15–6.87 ms，没有大于10 ms的间隔；两路力约1000 Hz。两轮试验各有180,000行有效1000 Hz网格，八路缺失均0，迟到/乱序/队列溢出/样本缓冲溢出均0。短时旧版也没出现IMU长空档；不能仅凭新版3分钟无空档就证明20分钟偶发问题彻底消失。


## 构建及回滚

构建必须保留 `hipexo_motor_schedule.h` 与C++源文件在同一目录。原 `build_motor_capture.py` 命令不变。

```bash
g++ -std=c++14 -O2 test_motor_schedule.cpp -o /tmp/hipexo_schedule_test
/tmp/hipexo_schedule_test
```

本机部署前已保存完整的本次修改文件备份。回滚需关闭界面、停止辅助进程，再恢复备份；不在采集中覆盖正在执行的辅助二进制。真实记录和原始波形保留本机，GitHub只包含代码、文档和汇总验收数字，原SIMULATED样例继续保留。
