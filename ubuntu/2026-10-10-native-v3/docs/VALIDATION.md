# V3 验收：四 IMU 200 Hz，电机接近原生 1 kHz

2026-10-10，Jetson本机，沿用既有25W模式和CPU频率上限。四IMU、ADS8688两通道、两路GO-M8010-6零输出反馈同时采集，Qt offscreen主窗口实际show，六个页面轮换显示，每页约30秒。没有执行带负载的主动控制。本轮未连接Windows EMG/LiDAR；未检测到相机。

- 最终接受并保存 **863,014帧**，迟到0、乱序0、记录队列溢出0、样本缓冲溢出0，记录错误null。
- Motor 0：发送179,487，有效反馈179,487；Motor 1：发送179,751，有效反馈179,751。两路坏字节0、发送错误0。有效反馈数量也分别等于原生CSV的电机行数。协议没有请求序号，此处是数量核对，不能声称已经逐请求匹配。
- 两路错过的完整发送调度周期计数110/95；该计数不包含所有最小间隔保护引起的时间偏移。最终平均速率须从真实时间戳计算，不能只拿计数证明精确1000Hz。
- 电机应用IPC队列峰值各756字节；另有内核socket缓冲，不将756字节当成整个链路的总内存。原生发送队列硬上限256KiB。
- 主记录队列峰值86项、809,600字节，低于原有2048项/64MiB限制；没有扩容主记录队列。
- 时钟源结束后读取为136000000Hz、`mrq_rate_locked=0`；SPI和两条I²C的`power/control`均恢复`auto`。

聚合证据见 `gui_v3_180s_summary.json`。真实波形及采集目录只留本机。Qt事件循环计数不是显示FPS；offscreen不代表真实相机图像和桌面显示服务器的全部负载。

## 如何解决186Hz

I²C-1原配置100kHz，两个传感器必要寄存器的成对读取约5.2ms，无法装进5ms周期。用SMBus分段、组合I2C消息、连续寄存器读取比较后，纯读法调整没有足够改善。只对匹配的本机I2C2时钟做136→204→136MHz可逆对照，成对读取率约193→277→193Hz，未发生读错误。正式调度仍限制200Hz，不把277Hz当成IMU硬件输出率。见 `i2c_read_modes.json`、`i2c_clock_probe.json`，公开文件剔除了实测寄存器值。

这是整条总线的源时钟调试覆盖，未测SCL线频率，未修改设备树为400kHz。共享器件、运行条件、权限失败和回滚限制见README。

## 电机稳定性与ADC回归修复

首个独立C++12秒试验约998Hz且无坏帧，但初次20秒多传感器联测仍有少量坏字节。加入750µs最小发送间隔、禁止突发补发后，完整界面60秒两路均无坏帧、发送/有效反馈数相同。之后两次180秒完整界面测试均保持电机坏字节0和数量一致。

第一次180秒发现力数据出现61.8/51.3/43.3ms空档，均在20样本批次边界，平均降至999.15Hz。该结果不作为最终验收，保留 `before_adc_ipc_fix.json`。将ADC数据交接改为非阻塞、有256KiB上限的队列后，最终180秒两路恢复1000Hz，最大间隔约2.4ms。采集不会因短时交接等待而停下来，也不会无限积压；持续过载会报错。

## 回归测试

38项采集/保存测试通过，包含11项新增时钟、原生电机、切换独占和有界IPC测试，以及V2的27项测试。伪终端测试验证每条电机命令的零参数与CRC，坏帧过滤、停止和父进程消失后退出；没有以真实运动测试替代这些验证。

57项旧界面、EMG、IMU参考姿态、断线状态和记录布局回归全部通过，耗时73.7秒；合计95项不同测试通过。最终辅助程序重编译后，3项原生协议/IPC测试再次通过。完整命令在 `TESTING.md`。

V2的180秒模拟全传感器+图像写盘验证仍是继承的存储层证据，本轮没有把它改名为V3新的全硬件验收。V3实机范围仅为上述四IMU、两力和两路零输出电机。
