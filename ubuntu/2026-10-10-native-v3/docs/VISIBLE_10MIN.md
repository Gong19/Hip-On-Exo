# 真实桌面实时波形：10分钟内存与采集验收

结论：在本次1920×1080真实桌面界面、实时波形运行的600秒试验内，未发现内存不足导致的记录丢失；但界面刷新性能未达到20 Hz设置值。

窗口使用Qt xcb/X11真实显示，每30秒轮换Motor、IMU、Force三页。60次状态快照均可见、未最小化，定时器运行；有实际曲线更新、绘制事件和桌面窗口截图。有效窗口精确600秒，原记录另含启动及收尾。

界面和采集/写入子进程RSS合计采样峰值524.6 MiB；界面主进程峰值447.2 MiB。第3–6分钟总RSS中位数518.9 MiB，最后3分钟515.8 MiB，后段未持续增长。系统可用内存最低2.43 GiB。RSS每10秒采样，合计可能重复计入共享页，不能当作精确物理内存或瞬时峰值。

系统交换区已有使用且有后台交换活动，包含其它应用；额外抽查各采集进程VmSwap均为0。不能把系统全部交换区使用归因于本应用。

实际原生频率：电机999.249/999.124 Hz；两路力约1000 Hz；四路IMU寄存器读取约200 Hz。电机两路各有一次大于10 ms的主机反馈间隔，最大11.448/11.382 ms；未声称每帧严格1 ms。

两路电机最终发送数、有效反馈数与原生CSV条数分别一致；坏字节和发送错误均0。IMU没有大于10 ms空档，最大约6.18–7.34 ms，未重现之前约200 ms的共同停顿。

1000 Hz有效网格600,000行，八路缺失均0、索引连续；迟到、乱序、队列溢出、样本缓冲溢出均0。记录端待写队列峰值0.723 MiB，低于64 MiB上限。队列和反馈计数不能证明设备内部绝对无丢样。

实际可见页平均重绘：Motor 6.49次/秒；IMU 1.67次/秒；Force 4.22次/秒。事件处理循环最大间隔959.2 ms。采集频率与显示刷新率必须分开看；绘图/界面响应是待优化项，尚未做耗时剖析来确认具体瓶颈。

范围：四IMU、两路力、两路电机零输出反馈；相机、LiDAR、Windows EMG未启用。外骨骼悬挂静止。本次不是已知载荷/运动精度标定，也不证明任意时长或接入更多设备后仍满足同样表现。

先打开「打开查看信号.html」。plots/05_visible_memory_and_refresh.png是内存与刷新图；screenshots/是实验中的真实界面截图。data/保留完整原生CSV、1000Hz表、字段说明和300ms周期索引。真实信号及截图仅保存在本机。

## 重现

源码版本为V3.3，默认电机请求1000 Hz，保留调度时间表和IMU非阻塞交接修复。使用 `python/benchmark_visible_10min.py`；它针对当前工作站，默认从 `/home/gong/Desktop/exo-control (copy)/python` 导入已部署模块，SDK和私有硬件配置由本机提供。先关闭其它采集程序，并确保X11会话可见。

```bash
mkdir -p evidence
DISPLAY=:0 XAUTHORITY=/run/user/1000/gdm/Xauthority python3 benchmark_visible_10min.py
```

启动时等待窗口真正exposed，之后才开始采集；所有八路就绪并预热3秒后才计600秒。以原有绘图方法和setData调用计数验证实时更新，未提高绘图目标频率，也未替换为静态图片。可见性断言失败或记录被中断会标记实验失败。完成时停止传感器、排空记录并关闭测试窗口；I²C源时钟及控制器电源策略已恢复。

测试程序还执行少量状态采样和四次窗口截图，这些开销包括在本轮结果里。没有同条件“显示关闭”的对照，因此不把前后不同版本/时长的RSS差值当作纯绘图开销。
